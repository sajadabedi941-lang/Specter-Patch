Deploy explosion (v3 confirmed in-game; v4 cause from EA ZH source)
--------------------------------------------------------------------
Observed blast is Object USAPAC3 SlowDeath ModuleTag_L8F09
(DeathTypes ALL -SPLATTED -EXTRA_8):
  FX_CrusaderCatchFire + FX_GenericFreeFallBombsExplosion
  + OCL_ThaadDeathEffect
That module cannot run if S400R_Deploy applied DeathType SPLATTED.

Proven command chain (shared buttons / weapon, not edited):
  Command_AADS_AA_Mode -> S400ECommandSet_AA
  Command_ADSCombatMode
    Command = FIRE_WEAPON, WeaponSlot = SECONDARY, MaxShotsToFire = 1
  ControlBarCommandProcessing.cpp
    -> GameMessage::MSG_DO_WEAPON
  GameLogicDispatch.cpp MSG_DO_WEAPON
    -> setWeaponLock(SECONDARY, LOCKED_TEMPORARILY)
    -> groupAttackPosition(NULL)  // NULL = attack own position
  AIGroup.cpp
    -> aiAttackPosition(self pos, 1)
  DeployStyleAIUpdate.cpp update()
    current weapon = S400R_Deploy (AttackRange default 0)
    isWithinAttackRange(self, self pos): distSqr 0 <= 0 -> in range
    READY_TO_MOVE + in range -> setMyState(DEPLOY)
    MODELCONDITION_UNPACKING for UnpackTime 5000, then DEPLOYED
    only then parent AI is allowed to fire
  Weapon S400R_Deploy (if it actually fires)
    DamageType EXPLOSION, DeathType SPLATTED
    RadiusDamageAffects = SELF SUICIDE, PrimaryDamage 10000
    SlowDeath NONE +SPLATTED -> OCL_US_PAC3_Deployed
      US_PAC3_FireControlSystem + AirdefenseLinkRestarter
      + US_PAC3_CombatMode (Model UsaPac3F, no Animation=)

S400R_Deploy is therefore NOT the first thing the engine does.
Unpack runs first. TurretsFunctionOnlyWhenDeployed and
ManualDeployAnimations do not skip that (v3 in-game still exploded;
source confirms those flags only toggle turrets / animation frames).

THAAD difference that actually matters:
  US_THAAD keeps DeployStyleAIUpdate AND Draw UNPACKING/DEPLOYED
  with a real US_M1120.US_M1120 clip, so unpack completes and
  S400R_Deploy can fire SPLATTED.
  US_THAAD_CombatMode already uses AIUpdateInterface for the same
  FIRE_WEAPON suicide (S400R_Pack) and does not unpack first.
  USAPAC3 Draw has no UNPACKING/DEPLOYED ConditionState and no
  unpack clip, so the DeployStyle gate never reaches SPLATTED.

v4 fix (US_PAC3.ini only; ART TWO unchanged from v2):

    (same as US_THAAD_CombatMode / US_PAC3_CombatMode)

Crash fix (v2) — why the first pack still crashed
-------------------------------------------------
W3DTruckDraw on Object USAPAC3 (KindOf PRELOAD) preloads every Model
and Animation named in the Draw module at game start / spawn.
UsaPac3Car.UsaPac3Car is a 101-frame clip with only BIT_CHANNEL tracks
(not a THAAD-style deploy transform). The previous USAPAC3 already
crashed after the empty UsaPac3F Animation= was stripped; the remaining
preload was this Car clip plus W3DTruckDraw tire setup. v1 also added a
second W3DTruckDraw (UsaPac3Car_w) with ConditionState=NONE and no
DefaultConditionState.

v2 changes (TEL objects only; US_THAAD untouched):
  Draw = W3DModelDraw, model-only Car / Car_d / deployed F / F_d
  no Animation= lines
  no second tire Draw
  PRELOAD removed from USAPAC3 / CombatMode / PackMode KindOf
  ART: delete 0x200 chunks from UsaPac3Car, UsaPac3Car_d, pac3mis_m,
       UsaPac3Car_w

Fire chain, slot 6, and loose Data\INI are unchanged. Still not an
in-game test.
